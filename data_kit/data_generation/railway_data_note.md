# Ujjwal Rail synthetic operational data note

This dataset contains wholly fictional stations, trains, passengers and bookings for a one-day hackathon demonstration. No real passenger data, IRCTC data, or real booking records were used. The checked-in run used the curated creative catalog in `railway_data/generator.py`; no external LLM generated it because the installed Ollama client could not reach its local service. The generator exposes `--ollama-model` for a future creative-catalog run and records the actual choice in `railway_generation_log.json`.

Python deterministically assigns IDs, routes, running days, chronologically valid stops, fare amounts in integer paise, 14-day service inventory, bookings, traveller allocations and policy-boundary timestamps. The fixed seed is 42 and the default reference date is 2026-11-21. Times include the Asia/Kolkata offset. Booking `journey_date` is the train's origin departure date; `boarding_datetime` identifies the traveller's boarding event.

`stations`, `trains` and `train_stops` describe the network. `fares` contains every supported class and ordered station pair. `train_capacities` defines CNF, RAC and waitlist quotas. `seats` stores remaining quotas after active allocations. This intentionally simplified model shares inventory across the whole train/class and does not reuse seats by route segment. `passengers`, `bookings` and `booking_travellers` support customer history and status queries. `train_service_cancellations` separates operator disruption from passenger cancellation. `actions` is created empty for later preview-confirm-execute workflows. Existing policy `settings` remain under their original module.

Traveller codes are CNF, RAC and WL. Booking labels are CONFIRMED, RAC, WAITLISTED, MIXED, CANCELLED and OPERATOR_CANCELLED. Cancelled records retain historical traveller allocations but do not consume active inventory. Operator-cancelled services have zero usable inventory.

Deliberate cases cover an exact cancellation cutoff and one minute after it, an overnight train, mixed CNF/WL travellers, a passenger with no bookings, ambiguous station aliases, RAC/waitlist/full inventory states, and an operator-cancelled service. Validation checks counts, dates, route chronology, weekday service, fares, allocation/capacity reconciliation, status consistency, schema, settings preservation and SQLite foreign keys. Automated tests exercise the same high-risk boundaries. Generated JSON is canonical and reviewable; SQLite is a transactional serving copy.
